# DUM BARBERSHOP Platform — Product Blueprint

版本：1.0  
狀態：Baseline  
適用範圍：官方網站、預約、員工操作、客戶資料、會員預留、Apple 生態整合

---

## 1. 專案願景

建立一個符合 DUM BARBERSHOP 審美與營運方式的深色數位平台，讓品牌展示、作品、服務、多人預約、員工行程與客戶紀錄集中在同一套可演進架構中。

本平台不是單純形象網站，也不是把第三方預約頁直接貼上去，而是：

> DUM 的品牌入口、客人預約入口與多人工作室營運基礎。

品牌形象、作品展示、線上預約與營運效率彼此平衡，目前不指定單一目標為唯一最高優先。

## 2. 已知營運前提

- 店家：DUM BARBERSHOP
- 型態：單店、多人工作室
- 目前沒有分店
- 客人可以指定設計師
- 一般客人不需登入即可預約
- 未來會員可以登入並綁定店內會員資料
- 目前會員系統尚未規劃完成
- 必須保存客戶與服務歷史
- 現在以 Google Calendar 手動管理預約
- 手機與 Apple Watch 是重要管理裝置
- 訂金不是全面強制，但需要預留可選訂金與優先機制

## 3. 品牌與視覺方向

### 3.1 整體氣質

- 深色
- 美式
- 硬派
- 成熟
- 幫派感
- 工業感
- 精品感
- 乾淨俐落
- 不廉價、不花俏、不像一般美容院模板

### 3.2 視覺原則

- 以近黑、炭黑、深灰為主要背景
- 灰白作為主要文字
- 霧金或暗紅只作為少量重點色
- 大圖、大標題、清楚層級
- 動畫短、穩、乾淨
- 手機單手操作優先
- 預約按鈕在手機版保持容易觸及
- 避免過多霓虹、廉價金色、過度圓角與遊戲介面感

### 3.3 設計系統要求

色彩、字型、間距、圓角、陰影、動畫與元件狀態必須集中管理，不得散落在頁面內寫死，方便後續統一調整。

## 4. 使用者角色

### 4.1 訪客

- 瀏覽品牌、作品、服務與設計師
- 查看店家資訊
- 不登入也能預約

### 4.2 一般客人

- 選擇服務
- 指定或不指定設計師
- 選擇日期與時段
- 填寫基本資料與備註
- 查看、取消或改期自己的預約
- 接收預約提醒

### 4.3 會員客人（未來）

- 綁定既有店內會員身分
- 自動帶入資料
- 查看歷史預約
- 查看儲值、次數、點數或會員權益
- 快速再次預約慣用服務與設計師

### 4.4 設計師

- 查看個人整日行程
- 查看下一位客人
- 查看必要客戶資料與備註
- 封鎖時段
- 標記到店、進行中與完成
- 管理自己的可預約時間與休假（依權限）

### 4.5 店主 / 管理者

- 查看全店行程與設計師負載
- 管理服務、價格、時長、排班與權限
- 管理預約、等候名單、取消及改期
- 查看客戶歷史與店務資料
- 管理未來會員、訂金與通知政策

## 5. 官方網站資訊架構

### 5.1 首頁

建議區塊：

1. 主視覺與品牌標語
2. 立即預約
3. 熱門服務
4. 精選作品
5. 設計師介紹
6. 店內特色
7. 顧客評價
8. 地址、營業時間與地圖
9. LINE、Instagram、電話及導航

### 5.2 服務與價目

每個服務至少包含：

- 服務名稱
- 分類
- 簡介
- 價格或起價
- 預估時間
- 可服務設計師
- 注意事項
- 預約入口

預留分類：剪髮、修面、燙髮、染髮、頭皮護理、組合服務、活動方案。

### 5.3 設計師

每位設計師頁面可包含：

- 名稱
- 照片
- 職稱
- 簡介
- 擅長項目
- 作品
- 可預約服務
- 可預約時段入口

### 5.4 作品

預留分類：

- Skin Fade
- 短板前刺
- 凱撒頭
- 飛機頭
- 油頭
- 寸頭
- 黑人燙
- 雷鬼頭
- 染髮
- 素人改造

### 5.5 線上預約

採多步驟流程：

1. 選服務
2. 選設計師或不指定
3. 選日期
4. 選時段
5. 填客戶資料
6. 填需求與備註
7. 選擇是否使用可選訂金
8. 確認預約須知
9. 建立預約
10. 顯示成功、提醒與加入行事曆選項

### 5.6 會員專區

第一階段只預留入口與資料模型，不建立正式登入、儲值、點數或付款。

### 5.7 關於 DUM

- 品牌故事
- 理念
- 專業特色
- 店內環境
- 地址與營業資訊

### 5.8 聯絡與政策

- 電話
- LINE
- Instagram
- Google Map
- 停車與交通
- 預約須知
- 取消與遲到政策
- 訂金政策
- 隱私權與個資告知

未確定政策先標示為待 Owner 決策，不得發布假規則。

## 6. 預約核心需求

### 6.1 多設計師模型

- 每個預約必須對應一位實際設計師
- 客人可以指定設計師
- 可預留「不指定」並由系統提供最早可預約選項
- 每位設計師有獨立排班、休假、服務能力與封鎖時間
- 同一設計師不可重複預約
- 服務時長、前後緩衝與店內資源限制需可配置

### 6.2 預約狀態

建議基礎狀態：

- `pending`
- `confirmed`
- `checked_in`
- `in_service`
- `completed`
- `cancelled_by_customer`
- `cancelled_by_shop`
- `no_show`
- `rescheduled`
- `waitlisted`

狀態轉換必須集中在 Booking Domain，不得由畫面任意改字串。

### 6.3 訂金狀態

訂金與預約狀態分離：

- `not_required`
- `unpaid`
- `pending`
- `paid`
- `refunded`
- `partially_refunded`
- `forfeited`

第一階段只預留資料結構與 UI，不啟用真實金流。

### 6.4 訂金優先

已確認方向：訂金客可獲得較高優先權。

安全預設：

- 不自動擠掉已確認的免訂金預約
- 優先套用於等候名單
- 優先套用於新釋出的空檔
- 優先套用於尚未確認的請求
- 任何會改動已確認客人權益的規則都必須由 Owner 明確批准

## 7. Google Calendar 定位

Google Calendar 目前是手動預約工具，未來保留並整合。

目標用途：

- 設計師個人行程顯示
- 店務行程顯示
- iPhone / Apple Watch 提醒
- 手動建立忙碌或封鎖時段
- 與預約核心同步

正式架構中：

- 預約核心管理完整狀態、客戶資料、會員、訂金與歷史
- Google Calendar 管理顯示、提醒、外部忙碌事件與時間封鎖
- 同步必須處理衝突、重複、刪除、時區與延遲

第三方預約供應商尚未定案，核心透過 Adapter 接入。

- 今日行程

- 下一位客人

- 預約詳情

## 9. Apple Watch 功能分級

### Tier A — 行事曆即可完成

- 查看整日行程
- 查看預約時間
- 查看下一位客人
- 接收提醒
- 透過行事曆建立忙碌 / 封鎖事件

### Tier B — Apple Shortcuts + API

- 快速封鎖 30 / 60 分鐘
- 查詢下一位客人
- 查詢今日行程
- 標記客人已到
- 標記完成
- 快速聯絡客人

### Tier C — 原生 watchOS App

只有在 Tier A 與 Tier B 無法滿足日常操作時才評估：

- 搜尋客人
- 更完整預約詳情
- 快捷狀態操作
- 專屬錶面元件

第一版不得承諾原生 watchOS App。

- LINE / Email（選填）
- 建立時間
- 最後到店時間
- 慣用設計師
- 會員關聯欄位
- 聯絡與行銷同意狀態

### 10.2 服務歷史

- 預約與服務日期
- 設計師
- 服務項目
- 服務時長
- 價格
- 技術備註
- 客戶偏好
- 使用產品
- 預約來源
- 訂金狀態
- 完成 / 取消 / 爽約狀態

## 13. 非功能需求

- 手機優先、響應式
- 繁體中文優先
- 基本無障礙與鍵盤操作
- SEO 基礎
- 圖片最佳化
- 清楚的 Loading、Empty、Error 狀態
- 時區以 `Asia/Taipei` 為營運預設，但資料儲存需採標準時間格式
- 不提交秘密與真實個資
- 預約寫入需防重複與競態
- 外部整合失敗時不可默默遺失預約
- 重要操作需保留稽核紀錄

## 14. 第一階段交付範圍

只建立框架與 Mock 流程：

- 深色設計系統
- 官方網站主要頁面
- 多步驟假預約流程
- 假服務、設計師、時段與客戶資料
- Staff App 原型
- 會員預留頁
- Domain 型別與 Adapter 邊界
- README、架構與本機啟動方式

第一階段禁止：

- 真實預約寫入
- 真實 Google Calendar 串接
- 真實通知
- 真實付款
- 正式會員登入
- 真實客戶資料
- 擅自發布營運政策
